# 钉钉与企业微信绑定

用户先用账号密码登录管理端，再在个人中心把钉钉或企业微信绑到当前账号。扫码不会自动创建用户。未绑定的账号扫码登录会失败。

登录页上的社交图标由网站配置里的「社交登录」开关控制。个人中心的绑定不依赖这个开关，但依赖密钥管理里已经保存的应用。

## 在本系统填写 {#keys}

路径：密钥管理 → 外部密钥 → 新增。每种类型只保留一条。授权时按类型取这一条。

| 系统字段 | 钉钉 | 企业微信 |
|----------|------|----------|
| 类型 | `DINGTALK` | `WEIXIN_CP` |
| appId | 应用凭证里的 Client ID（原 AppKey） | 企业 ID（corpid） |
| appSecret | 同一页的 Client Secret（原 AppSecret） | 自建应用的 Secret |
| 拓展字段 | 留空 | 该自建应用的 AgentId，只写数字 |
| 回调地址 | 与下面「实际回调」相同的完整地址 | 与下面「实际回调」相同的完整地址 |

不要把 AgentId、CorpId 填进钉钉的 appId。企业微信的拓展字段不要写成 JSON，也不要加引号。应用详情上的 AgentId 是 `1000002`，就填写 `1000002`。

Secret 在企业微信里点「查看」后发到管理员的企业微信，只在手机上显示一次。

## 实际回调 {#callback}

授权链接不读取密钥管理里保存的回调地址，而是用当前浏览器地址栏拼出来：

```text
{协议}://{主机}:{端口}/#/authredirect
```

用 `http://127.0.0.1:8888` 打开管理端时，回调是 `http://127.0.0.1:8888/#/authredirect`。用域名打开时，主机和端口换成地址栏里的值。开放平台登记的域名必须和这次打开管理端的地址一致，包含端口，不支持把 `localhost` 和 `127.0.0.1` 当成同一个地址。

## 钉钉 {#dingtalk}

在[钉钉开发者后台](https://open-dev.dingtalk.com)创建企业内部应用。凭证页同时有 App ID、AgentId 和 Client ID，授权只用 **Client ID** 和 **Client Secret**。

1. 开发配置 → 安全设置，重定向 URL 填写[实际回调](#callback)的完整地址，包含协议和 `/#/authredirect`。
2. 权限管理开通个人权限「通讯录个人信息读权限」（`Contact.User.Read`）。
3. 应用发布 → 版本管理与发布，至少有一个已上线版本。未发布时，凭证页能复制 Client ID，打开授权页仍会返回 900103「应用不存在」。

官方步骤见[获取登录用户的身份凭证](https://open.dingtalk.com/document/development/obtain-identity-credentials.md)。

绑定成功后，钉钉返回的 `openId` 写入当前用户的 `wx_ding_userid`。

## 企业微信 {#wecom}

在[企业微信管理后台](https://work.weixin.qq.com/wework_admin/frame)用管理员创建自建应用。参数位置见[基本概念](https://developer.work.weixin.qq.com/document/path/90665)。

| 参数 | 位置 |
|------|------|
| 企业 ID | 我的企业 → 企业信息 |
| AgentId | 应用管理 → 自建 → 该应用详情 |
| Secret | 同一详情页，点查看后在企业微信手机端接收 |

授权域名有两处，都只填主机和端口，不要写 `http://`，也不要写 `/#/authredirect`。说明见[企业微信网页授权登录](https://developer.work.weixin.qq.com/document/path/98173)。

1. 该应用 → 企业微信授权登录 → Web 网页 → 设置授权回调域。
2. 同一应用 → 网页授权及 JS-SDK →「可作为应用 OAuth2.0 网页授权功能的回调域名」。

第 2 处不接受 IP、`localhost` 和短链域名，并且要求域名已备案，备案主体与当前企业主体相同或有关联。本地开发时把这个域名解析到本机，再用 `http://该域名:端口` 打开管理端。回调对不上时，扫码页提示「redirect_uri 与配置的授权完成回调域名不一致」。

绑定成功后，企业微信返回的 `userid` 写入当前用户的 `wx_cp_userid`。

## 绑定和登录 {#flow}

1. 管理员先保存对应类型的密钥。
2. 用户用账号密码登录。
3. 打开个人中心，在企业微信或钉钉一行点击绑定。
4. 在弹出的授权页完成同意。企业微信是扫码，钉钉是登录授权。
5. 授权方回到 `/#/authredirect`，页面调用 `POST /admin/social/bind`。
6. 个人中心该行变为已绑定。解绑会清空对应的用户标识。

之后可以在登录页再次扫码。登录要求网站配置已打开社交登录，并且该用户已经绑定。系统用绑定时保存的标识查找用户，找不到就不登录。
